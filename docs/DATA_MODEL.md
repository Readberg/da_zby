# DATA_MODEL — схема данных

Источник истины: `supabase/migrations/*.sql`. Этот документ — карта; при изменении схемы обновлять его в том же PR.
Миграции `20261024000000_init.sql` и `20261024000100_bootstrap_admin_and_kind.sql` проверены на Postgres 16 сценариями: самоповышение роли, чужие прогнозы, дедлайн, автоподсчёт, пересчёт, закрытие и откат сезона, запрет снять последнего админа.

## Таблицы

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `profiles` | Публичный профиль (1:1 с `auth.users`) | `nickname` (citext, уникальный, NULL до онбординга), `full_name`, `contact`, `about`, `avatar_path`, `country_code`, `city`, `utc_offset_minutes` (по умолч. 180), `role` (`user`/`admin`), `created_at`, `last_login_at` |
| `profile_private` | Приватные данные | `user_id`, `email` (видит владелец и админ) |
| `tournaments` | Турниры и их настройки | `name`, `slug`, `kind` (сейчас только `score_prediction`), `points_exact` (3), `points_outcome` (1), `is_active` |
| `seasons` | Сезоны турнира | `tournament_id`, `name`, `status` (`active`/`closed`), `closed_at` |
| `clubs` | Общий справочник клубов | `name`, `short_name`, `logo_path` |
| `season_clubs` | Состав клубов сезона | `season_id`, `club_id` |
| `tours` | Туры сезона | `season_id`, `number`, `title`, `deadline_override` |
| `matches` | Матчи тура | `tour_id`, `home_club_id`, `away_club_id`, `kickoff_at`, `status` (`scheduled`/`finished`/`postponed`/`cancelled`), `home_score`, `away_score` |
| `predictions` | Прогнозы | `user_id`, `match_id`, `home_score`, `away_score`, `result` (`exact`/`outcome`/`miss`/NULL), `points` — уникально (user, match) |
| `admin_bootstrap` | Кому выдать роль админа при первом подтверждённом входе (клиентам недоступна) | `email`, `nickname` |
| `season_standings` | Зафиксированные итоговые места сезона | `season_id`, `user_id`, `final_rank`, очки и счётчики |

Представления (с `security_invoker`): `season_leaderboard`, `tour_leaderboard` — счётчики, очки, `current_rank` (rank() по очкам → точным счетам → исходам), в сезонном ещё `final_rank`, `wins_count`, `losses_count`, `win_rate`.

Storage: бакеты `avatars` (2 МБ, jpeg/png/webp, пишет владелец в свою папку `<uid>/`) и `club-logos` (1 МБ, пишет только админ). Оба публичны на чтение.

### `login_tokens` (0.6.0, D-056)
Одноразовые попытки входа через бота: `token_hash` (SHA-256 токена, PK), `code` (число на экране), `expires_at` (10 минут), `telegram_id/username/first_name/last_name` и `confirmed_at` (заполняются, когда выбрано верное число), `consumed_at` (токен обменян на сессию). RLS включён без политик, права anon/authenticated отозваны: только ключ сервиса.

### `chat_messages`, `chat_bans` (DAZBY-117, D-098)
Общий чат. `chat_messages`: `id`, `user_id` → `profiles`, снимок автора `author_nickname` / `author_avatar_path` (заполняет триггер, клиент подделать не может), `body` (1–500 символов), `created_at`. Живёт 3 дня (с 29.10.2026, раньше 24 часа): чтение закрыто политикой (`created_at > now() - 72 часа`), физически строки удаляет `purge_chat_messages()` — после каждой вставки и по расписанию pg_cron раз в 10 минут. Читают только вошедшие (`authenticated`); пишет вошедший от своего имени (права только на колонки `user_id`, `body`); удаляет автор свои, админ любые. Триггер до вставки отказывает забаненному (`chat.banned`), пользователю без ника (`chat.no_nickname`) и чаще одного сообщения в 2 секунды (`chat.rate_limited`). `chat_bans`: `user_id` (PK), `banned_at`, `banned_by`; все операции только у админа, свой статус участник узнаёт через `chat_is_banned()`. Таблица добавлена в публикацию `supabase_realtime`. В резервные копии `chat_messages` не попадает (workflow `db-backup`).

### `mgr_cities`, `mgr_clubs`, `mgr_players`, `mgr_player_attributes`, `mgr_player_hidden` (DAZBY-143, D-129)
Футбольный менеджер, раздел сайта со своими таблицами. `mgr_cities`: `id`, `country`, `name` (25 городов Беларуси). `mgr_clubs`: `user_id` (уникален: один клуб на пользователя), `name` (до 30 символов, буквы и цифры, одиночные пробелы; уникально без учёта регистра), `country`, `city_id`, `primary_color`/`secondary_color` (разные, `#rrggbb`), `squad_seed` (из него один раз сгенерирован стартовый состав). `mgr_players`: `club_id`, имя, `position` (GK/DEF/MID/FWD), `citizenship`, `academy_club_id` (воспитанник; при переходах не меняется), `age`, `ovr` (общий рейтинг), `form`/`fitness`/`morale` (0–100, старт 80). `mgr_player_attributes`: `(player_id, attribute)` → `value` 1–99 (14 характеристик у полевого, 7 у вратаря; состав категорий можно менять без схемы). `mgr_player_hidden`: `potential` — потолок роста, **без политики и прав**: клиент его не читает. RLS: вошедший читает города, **свой** клуб, его игроков и характеристики (этап 2 расширит чтение до лиги); прямой записи с клиента нет. Клуб и состав создаёт только `mgr_create_club(...)` (security definer, право только у service role): отказывает второму клубу (`manager.club_exists`), занятому названию (`manager.name_taken`), неизвестному городу (`manager.city_unknown`) и любому составу, не равному стартовому (20 игроков, 2/7/7/4 по позициям, сумма `ovr` ровно 1200) — `manager.squad_invalid`.

### `mgr_leagues`, `mgr_matches`, `mgr_lineups` и изменения `mgr_clubs` (DAZBY-144, D-129, D-130)
Этап 2 менеджера. `mgr_clubs`: `user_id` стал необязательным (**бот** — клуб без пользователя, `is_bot`, связь проверяет check), добавлен `league_id`. `mgr_leagues`: `number`, `season`, `first_kickoff_at` (тур N играется через N−1 суток, в 07:00 UTC = 10:00 по Москве). `mgr_matches`: лига, тур (1–38), хозяин и гость, `kickoff_at`, `status` (scheduled/finished), счёт, `events` (хроника данными: минута, тип, фамилии), снимки составов `home_lineup`/`away_lineup` (имена остаются, даже когда бот уступил место клубу). `mgr_lineups`: состав клуба на ближайшие туры (расстановка, тактика, 11 игроков); нет записи или состав стал негодным — играет лучший автосостав без штрафа. RLS: вошедший читает свой клуб и **клубы, матчи и лигу своей лиги** (функция `mgr_my_league()`), состав — только своего клуба; прямой записи нет. Запись только функциями для service role: `mgr_join_league` (клуб занимает место бота: матчи и очки бота переходят клубу, бот удаляется), `mgr_open_league` (лига из 20 ботов и 380 матчей и место клуба — одна транзакция; лига из одних ботов не создаётся), `mgr_save_lineup` (проверяет 1 вратаря и линии расстановки; отказ после начала тура — `manager.lineup_locked`), `mgr_record_match` (результат пишется один раз; `false`, если другой запуск успел раньше).

### Этап 3, часть 1: поля `mgr_players` (DAZBY-145, D-131)
`injured_until` (травмирован до этого момента; пусто или в прошлом — здоров), `idle_rounds` (туров подряд без игры: каждый третий снижает мораль), `training_focus` (характеристика, которую игрок тренирует; пусто — отдыхает; должна быть среди его собственных). Матч и его последствия пишет одна функция `mgr_play_match` (service role): результат, хроника, составы **и** новые значения формы, физики, морали, рейтинга, характеристик и травм — в одной транзакции и один раз (второй запуск получает `false` и ничего не меняет). `mgr_set_training` проверяет, что игроки из клуба вызвавшего и характеристики у них есть; после начала тура отказывает (`manager.training_locked`). `mgr_save_lineup` теперь не принимает травмированных. Старая `mgr_record_match` остаётся (код её больше не вызывает; убрать позже отдельной миграцией).

### Этап 3, часть 2: сезон (DAZBY-146, D-132)
`mgr_leagues`: `phase` (`season` — 38 туров, `preseason` — 5 суток без матчей чемпионата), `preseason_ends_at` (когда начнётся следующий сезон), `last_tick_at` (последний день предсезонки с применённой тренировкой). `mgr_matches`: `season` (сезон лиги) и `kind` (`league` — тур 1–38, `friendly` — товарищеский, тур 0); уникальность матча теперь «лига + сезон + тур + клуб» только для матчей чемпионата. `mgr_players.retire_after_season` — игрок уйдёт на пенсию в конце ближайшего сезона. `mgr_close_season` (после 38-го тура): ушедшие на пенсию удаляются и заменяются молодыми игроками той же позиции (список передаёт сервер, база сверяет клуб и позицию), всем +1 год, форма/физика/мораль 80, у старше 33 лет решается пенсия (34 года — 50%, дальше +5% за год), фаза `preseason` до «последний тур + 6 суток». `mgr_open_season` (когда предсезонка кончилась): 380 матчей нового сезона, фаза `season`. `mgr_apply_preseason_day` — один день предсезонки (отдых и тренировка вдвое слабее), один раз в сутки. `mgr_request_friendly` — товарищеский матч на ближайшие 10:00 МСК только в предсезонку, одному клубу не больше одного в сутки; без соперника выбирает случайный свободный клуб лиги.

### Этап 4, часть 1: деньги и пул свободных игроков (DAZBY-147, D-133)
`mgr_clubs.budget` (игровые доллары, старт 10 000; может быть отрицательным — тогда покупки закрыты). `mgr_transactions`: журнал клуба (сумма, причина `base/tickets/premium/wages/prize/purchase/sale/tax`, ссылка на матч или игрока, баланс после); читает только владелец клуба, пишет только функция `mgr_pay`, поэтому бюджет всегда равен 10 000 плюс сумма журнала. `mgr_play_match_v2` пишет результат матча, его последствия для игроков и деньги тура в одной транзакции и один раз (деньги получают только реальные клубы; запись о не своём клубе или причине вне `base/tickets/premium/wages` отменяет всё). `mgr_close_season` в конце сезона платит призы реальным клубам по месту в итоговой таблице. **Свободный игрок** — строка `mgr_players` без клуба (`club_id` пуст) и с лигой пула (`pool_league_id`); читать его может клуб этой лиги. `mgr_add_pool` раз в месяц (`mgr_leagues.pool_month`) меняет нераспроданных на 30 новых. `mgr_buy_free_agent` продаёт игрока по номиналу (`mgr_nominal(рейтинг, возраст)`, та же формула, что в коде; тест сверяет): отказывает до 10 сыгранных матчей, при составе в 23 игрока, при бюджете ниже цены или отрицательном, и для игрока другой лиги.

### Интерфейс менеджера (DAZBY-149, D-134, D-135)
`mgr_save_lineup` и `mgr_set_training` закрываются за 5 минут до ближайшего матча клуба (раньше с его начала). `mgr_clubs.logo_path` — путь к логотипу клуба в бакете `avatars`, в папке владельца; `mgr_set_logo` проверяет путь (`<id владельца>/<имя>.jpg|png|webp`, без вложенных папок). `mgr_dev_fast_forward(n)` — только для разработки: сдвигает время начала матчей первых `n` туров каждой лиги в прошлое (D-135), удаляется перед запуском вместе с миграцией.

## Функции и триггеры

| Имя | Что делает |
|---|---|
| `is_admin()` | Проверка роли текущего пользователя |
| `set_user_role(target, role)` | Выдать/снять админа; нельзя снять последнего |
| `tour_deadline(tour_id)` | `deadline_override`, иначе (самое раннее начало матча тура − 10 минут) |
| `can_predict(match_id)` | Сезон активен, матч не отменён/завершён, дедлайн не прошёл |
| `grade_match()` (триггер на `matches`) | При `finished` + счёте проставляет `result`/`points` всем прогнозам матча; при выходе из `finished` — сбрасывает |
| `recalculate_season(season_id)` | Админ: пересчитать весь сезон (после смены очков турнира) |
| `close_season(season_id)` / `reopen_season(season_id)` | Зафиксировать итоговые места и закрыть сезон / откатить |
| `handle_new_user()`, `sync_auth_user()` | Создание профиля при регистрации; синхронизация email и последнего входа; вызов `apply_admin_bootstrap()` |
| `apply_admin_bootstrap(user, email, confirmed)` | Назначает админа и ник из `admin_bootstrap` **только при подтверждённой почте**; клиентам недоступна |

## Права (RLS и привилегии)

- Чтение: профили, справочники, рейтинги — всем, включая гостей; прогнозы — свои всегда, чужие после дедлайна тура (D-084). `profile_private` — только владелец и админ.
- Пользователь пишет: свой профиль (только колонки: ник, имя, контакт, о себе, фото, страна, город, часовой пояс — **не `role`**) и свои прогнозы (только `home_score`, `away_score`, и только пока `can_predict`). `result` и `points` клиент записать не может.
- Админ пишет: турниры, сезоны, клубы, состав, туры, матчи, логотипы клубов; вызывает функции управления.
- Первый админ: автоматически (`admin_bootstrap`: `wayreadberg@gmail.com` → роль admin, ник `Readberg`) при подтверждённом входе. Запасной ручной вариант: `update public.profiles set role = 'admin' where id = '<uuid>';` в SQL Editor.

## Известные особенности и риски

1. **Дедлайн вычисляется.** Если админ перенесёт самый ранний матч тура на более позднее время, дедлайн сдвинется вперёд. Чтобы зафиксировать, использовать `deadline_override`. Если понадобится строже — завести поле `deadline_at` и замораживать.
2. **Чужие прогнозы скрыты до дедлайна тура** (D-084, заменяет D-005): политика `predictions_select` отдаёт строку владельцу, админу и всем, когда дедлайн тура прошёл или матч завершён. Рейтинги (`season_leaderboard`, `tour_leaderboard`, `security_invoker`) читают прогнозы под правами смотрящего, поэтому до дедлайна они не включают чужие ещё закрытые прогнозы. Кеш рейтинга делается анонимным клиентом, поэтому в нём — только открытые прогнозы.
3. **Смена очков турнира** не пересчитывает старые оценки сама — нужна кнопка «пересчитать сезон».
4. **Часовой пояс** — фиксированный сдвиг от UTC, без перехода на летнее/зимнее время (в Беларуси переходов нет).
5. Удаление клуба, у которого есть матчи, запрещено (`on delete restrict`); удаление пользователя каскадно удаляет его прогнозы.

## Процесс изменений

1. Новая миграция `supabase/migrations/<timestamp>_<что>.sql`.
2. PR в `dev` (CI запрещает править уже существующие миграции) → после мержа workflow `db-migrate` сам применяет миграцию к dev (D-047).
3. Workflow сам проверяет схему глазами гостя (`scripts/check-schema.ts`) — красный прогон = миграция сломала права/объекты.
4. `pnpm db:types` — забрать сгенерированные типы из прогона и закоммитить.
5. Обновить этот документ и `CHANGELOG.md` (раздел «Миграции БД»).
