# ANALYTICS — события, воронка и наблюдаемость

Решение: D-079 (аналитика — D-064). Внешний сервис один — Umami Cloud; новых сервисов для ошибок не вводили.

## Что считаем (без персональных данных)

Umami считает посетителей без cookie. События не содержат ников, id, e-mail, адресов с параметрами — только «что случилось» и грубая деталь. Код: `src/lib/analytics.ts` (`track()`; если Umami не загружен — ничего не происходит и страница не ломается).

| Событие | Когда | Детали |
|---|---|---|
| `cta-click` | клик по главной кнопке (ссылки с `data-umami-event`) | `where`: `hero` (главная кнопка), `matches-all` («Все матчи»), `match` («Сделать прогноз» у матча), `header` («Войти» в шапке), `member` («Сделать прогноз» у вошедшего) |
| `login-code-shown` | показан код для выбора в боте Telegram | — |
| `login-confirmed` | код выбран в боте, вход подтверждён | — |
| `login-failed` | вход не начался или истёк | `reason`: `unavailable`, `start`, `expired` |
| `nickname-saved` | новый участник выбрал ник | — |
| `prediction-saved` | прогнозы сохранены | `count` — сколько матчей |
| `prediction-failed` | сохранить не удалось | `reason`: `closed` (тур закрылся), `error` |
| `faq-open` | открыт вопрос на главной | `question` — номер (1–8) |
| `theme-change` | тему переключили вручную | `theme`: `light` / `dark` |
| `client-error` | ошибка в браузере (окно, необработанное обещание, страница ошибки) | `message` (≤ 120 знаков), `path` (без параметров), `digest` (если есть) |

Просмотры страниц Umami считает сам.

## Воронка «первый прогноз» (настроить один раз в Umami)

Цель продукта — **первый прогноз за 20–30 секунд** после захода. В Umami: сайт → **Funnels** → новая воронка, окно 30 минут, шаги по порядку:

1. Просмотр страницы `/`
2. Событие `cta-click`
3. Событие `login-code-shown`
4. Событие `login-confirmed`
5. Событие `nickname-saved` (только у новых; можно сделать вторую воронку без этого шага)
6. Событие `prediction-saved`

Где воронка «течёт» — там и чинить: мало `cta-click` → текст и место кнопки; мало `login-confirmed` после `login-code-shown` → вход через бота (код, приложение Telegram); мало `prediction-saved` после входа → страница прогнозов.

## Наблюдаемость ошибок (без нового сервиса)

**Сервер.** Каждая ошибка — одна JSON-строка в логе Railway (`src/lib/log.ts`):
- `api.error` — необработанная ошибка в `/api/v1/*`: `requestId`, `method`, `route`, `status`, `error`, `message`, начало `stack`;
- `request.error` — ошибка страницы или обработчика, пойманная Next.js (`onRequestError`): `route`, `routeType`, `path` без параметров, `digest`;
- `telegram.webhook_failed`, `telegram.webhook_register_failed`, `videos.feed_failed` и т. п.
Искать в Railway → сервис → Logs по `"level":"error"` или по `event`. `requestId` совпадает с заголовком `X-Request-Id` ответа и полем `requestId` в ответе API.

**Браузер.** Событие `client-error` в Umami (Events). Если ошибка случилась в серверной части страницы, у события есть `digest` — найдите ту же строку `digest` в логе Railway (`request.error`).

**Доступность и здоровье.** `/api/v1/health/strict` + монитор GitHub (D-073) ловят падение сайта, базы и вебхука бота.

## Чего здесь нет сознательно

Sentry и подобные сервисы (трассировки, группировка ошибок, оповещения) — внешний платный сервис и новая обработка данных; вводить только отдельным решением владельца (запись в `docs/OWNER_TODO.md`). Пока объём (~1000 посетителей в месяц) покрывают логи и события Umami.
