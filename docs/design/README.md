# Библиотека дизайна «Да забей»

Здесь живёт всё, что нужно для единого вида сайта. Правило владельца: **ключевые элементы дизайна собираем сюда и переиспользуем, чтобы дизайн получался единым.**

## Состав

| Что | Где |
|---|---|
| Логотип и референсы | `logo.png`, `ref-posts-matches.png`, `ref-posts-table-score.png`, `ref-predictions-table.png` |
| Токены (цвета, шрифты, радиусы) | `docs/DESIGN.md` + код темы (Tailwind theme / CSS variables) |
| Каталог компонентов | `COMPONENTS.md` |
| Снимки компонентов | `components/*.png` (создаёт `pnpm design:snap`) |
| Снимки ключевых экранов | `screens/*.png` |
| Живая витрина | `/styleguide` (только dev) |

## Как пользоваться (для Claude)

1. **Перед созданием UI** открой `COMPONENTS.md`: если подходящий компонент есть — используй его, не делай копию.
2. **Нужен новый ключевой элемент** (кнопка нового вида, карточка, таблица, форма, бейдж, шапка, блок): создай его в `src/components/ui` (общий) или `src/features/<домен>/components` (доменный), добавь на `/styleguide`, запусти `pnpm design:snap`, **добавь запись в `COMPONENTS.md`** (имя, путь, варианты/состояния, когда использовать, когда нет, снимок).
3. **Новый экран** — после реализации сохрани снимок в `screens/` (мобильный и десктоп) и упомяни в `COMPONENTS.md` блоком «Экраны».
4. Не вводи новые цвета, шрифты и размеры вне токенов. Нужен новый токен — добавь в тему и опиши в `DESIGN.md`.
5. Изменение внешнего вида существующего компонента — это изменение для всех экранов; в PR перечисли, где он используется (правило №1).

## Как пользоваться (для владельца)

Открыть `/styleguide` в dev (`pnpm dev` → `http://localhost:3000/styleguide`) или посмотреть снимки в `components/`. Дизайнеру при финальном оформлении достаточно заменить токены и подправить компоненты из каталога.
